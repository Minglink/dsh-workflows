### R-01 NVIDIA Garak · Probe–Buff–Detector 三段解耦扫描架构
- 来源：WEB: https://github.com/NVIDIA/garak
- 槽位：评测流水线 / 探针编排框架
- 家族：F7（编码与格式戏法）＋ F8（智能体工作台规范）
- 浓度：高（工业界「LLM 版 Nmap」，将探测、扰动与判定完全解耦）
- 语义指纹：把「发什么探针（Probe）」「怎么变形（Buff）」「怎么判失守（Detector）」拆成三层独立可插拔插件，避免探针与裁判耦合失真。
- 机制要点：
  ・Probe 层按脆弱面分族（注入、泄漏、幻觉、越狱、编码、包幻觉等），保证覆盖度而非单一技巧；
  ・Buff 层作为正交变换管道（大小写、低资源翻译、编码、字符扰动）叠加在任意 Probe 上，天然形成组合矩阵；
  ・Detector 层支持多检测器并行打分（规则、分类器、语义裁判），输出标准化 Z-score 与基准对照；
  ・支持单行 CLI 与 JSONL 审计日志，便于跨版本回归对比。
- 剂量参数：
  - Probe 族覆盖范围：默认档 核心安全 6 族 / 保守档 单族定点扫描
  - Buff 扰动倍率：默认档 3 档轻量变换 / 保守档 仅原始基线
- 退化签名：若仅用关键词 Detector 易对长文本软拒误判（需与强语义裁判交叉核对）。
- 嫁接落点：对应「破甲制作 v3」`probe` + `bprobe` + `verify` 三段解耦规范；其 Buff 概念直接映射到 `stress_test` 的 BoN 微扰层。
- 风险与合规：仅在授权接口与测试环境运行批量扫描，遵守速率限制与平台服务条款。

### R-02 Microsoft PyRIT · 80+ Converter 与多轮 Orchestrator 编排器
- 来源：WEB: https://github.com/microsoft/pyrit
- 槽位：多轮红队编排器 / 变换管道
- 家族：F7（编码与格式戏法）＋ F6（元规则/优先级宪法）
- 浓度：高（微软官方开源生成式 AI 红队框架，覆盖单轮、多轮、多模态与树搜索）
- 语义指纹：用可串联的 Converter 变换链 + 持久化 Memory + 多轮 Orchestrator（含 Crescendo/PAIR/TAP），把一次性试探升格为带记忆的长期战役。
- 机制要点：
  ・内置 80+ 种 Converter（编码、语体改写、多语翻译、音频/图像跨模态转换），支持多级串联；
  ・Orchestrator 将「攻击模型、目标模型、评分器」解耦，支持 Crescendo 等多轮动态追问；
  ・Memory 层全量落库每轮对话与评分，支持跨会话复盘与失败轨迹回放；
  ・Scorer 层区分 True/False 分类器、Likert 连续量表与组合评分器。
- 剂量参数：
  - Converter 串联深度：默认档 1–2 级（防语义失真） / 保守档 1 级低困惑度改写
  - 多轮最大深度：默认档 4–6 轮 / 保守档 3 轮（对齐 LLMs Get Lost 衰减纪律）
- 退化签名：Converter 叠层过深（≥3 级）导致目标模型无法解码或输出乱码，触发无意义低分。
- 嫁接落点：对应「破甲制作 v3」`generate` 变异算子库与 `stress_test` 多轮轨迹编排；其持久化 Memory 思想对齐「破甲制作 v3 → 破甲炼化 v2」的 `transfer_back.md` 回灌闭环。
- 风险与合规：遵守授权红队边界；跨模态测试需确保测试素材无版权与隐私风险。

### R-03 Promptfoo · 声明式 YAML 红队矩阵与 Agent/MCP 断言网关
- 来源：WEB: https://github.com/promptfoo/promptfoo
- 槽位：CI/CD 安全回归配置 / Agent & MCP 测试套件
- 家族：F8（智能体工作台规范）＋ F6（元规则/优先级宪法）
- 浓度：高（覆盖 50+ 漏洞插件、RAG/Agent/MCP 工具链与 OWASP LLM Top 10 合规映射）
- 语义指纹：把红队用例、策略插件与通过断言写成声明式 YAML，直接嵌进 CI/CD 流水线，让每次模型或提示词升级都自动跑安全回归。
- 机制要点：
  ・插件化漏洞目录（50+ 类）与策略化攻击包装（多轮、编码、角色、间接注入）正交组合；
  ・原生支持 RAG 管道、Agent 多步调用与 MCP Server 工具描述/权限边界测试；
  ・支持确定性断言 + LLM-as-a-Judge 组合评分，并输出可视化红队风险矩阵与合规报告。
- 剂量参数：
  - 策略组合维度：默认档 3 插件 × 2 策略 / 保守档 仅基线回归集
  - CI 门禁阈值：默认档 零高危失守 / 保守档 仅告警不阻断
- 退化签名：声明式静态模板在目标模型升级后易产生模板过拟合，需结合自适应探针定期刷新。
- 嫁接落点：对应「破甲制作 v3」`recon` / `infer_probe`（当 `input-surface` 选「Agent 工作台与 MCP 工具面」时）以及 `report` 的合规映射表；第五架构（Codex 精神型）工作台教令的评测基线。
- 风险与合规：MCP 工具面测试应在隔离沙箱内执行，禁止对生产工具链发射写操作探针。

### R-04 JailbreakBench · 标准化行为基准与可复现裁判协议
- 来源：WEB: https://github.com/JailbreakBench/jailbreakbench
- 槽位：标准评测基准 / 裁判规范
- 家族：F6（元规则/优先级宪法）
- 浓度：中（标准评测底座，决定“什么才算有效评测”）
- 语义指纹：提供 100 条标准化对齐行为（含良性对照）与统一裁判协议，终结“各家自选样本、自定裁判导致分数不可比”的乱象。
- 机制要点：
  ・明确区分有害行为集与语义配对的良性行为集（Benign Behaviors），强制并行汇报误拒率；
  ・公开历史攻击产物归档（Artifacts），支持新防御与新方法在同一坐标系下横向复现；
  ・固定系统提示与裁判模型口径，作为论文与工程评测的公共基线。
- 剂量参数：
  - 评测抽样比例：默认档 全量 100 行为 / 保守档 分层抽样 30 行为（每类 3 条）
- 退化签名：单裁判在边界软拒样本上存在漂移，需配合 CJE Oracle 抽检校准。
- 嫁接落点：对应「破甲制作 v3」`probe` 孪生锐度对照与 `verify` 裁判校准卡。
- 风险与合规：遵守基准发布方的学术研究许可，不将基准输出用于真实危害场景。

### R-05 HarmBench · 功能与语义双维分类的自动化红队基准
- 来源：WEB: https://github.com/centerforaisafety/HarmBench
- 槽位：标准评测基准 / 分类器规范
- 家族：F6（元规则/优先级宪法）
- 浓度：中（CAIS 发布的标准化自动红队与鲁棒拒答评测框架）
- 语义指纹：按「标准行为 / 上下文相关行为 / 版权行为 / 多模态行为」四大功能维度划分测试集，并用专用微调分类器统一裁定。
- 机制要点：
  ・将「上下文依赖型风险」与「零上下文风险」分离，避免模型靠关键词硬拒刷高分；
  ・提供统一的多方法横向评测协议（覆盖白盒、黑盒、多轮与迁移攻击）；
  ・强调鲁棒拒答（Robust Refusal）与防御泛化能力对比。
- 剂量参数：
  - 功能维度权重：默认档 标准 + 上下文双维并重 / 保守档 仅标准维
- 退化签名：专用分类器跨分布迁移时可能出现阈值漂移（见 arXiv:2608.09624），需在 `verify` 阶段做异源双裁判复核。
- 嫁接落点：对应「破甲制作 v3」`analyze` 三维拒绝几何与 `verify` 消融审计。
- 风险与合规：仅供模型安全评测与防御对齐验证使用。

### R-06 EasyJailbreak · Selector–Mutator–Constraint–Evaluator 四元统一范式
- 来源：WEB: https://github.com/EasyJailbreak/EasyJailbreak
- 槽位：演化搜索架构 / 变异算子框架
- 家族：F7（编码与格式戏法）＋ F5（编辑室/创作工坊）
- 浓度：高（把十余种主流越狱算法抽象为同一套四组件流水线）
- 语义指纹：任何自动化红队算法都可拆成「选种子（Selector）→ 施变异（Mutator）→ 过约束（Constraint）→ 打分淘汰（Evaluator）」四步循环。
- 机制要点：
  ・Selector 负责按历史得分/新奇度挑出下一轮父本；
  ・Mutator 封装语言改写、翻译、跨代交叉、角色嵌套等原子算子；
  ・Constraint 负责过滤语义漂移或超出长度/困惑度上限的无效变异体；
  ・Evaluator 给出连续反馈分驱动下一代进化。
- 剂量参数：
  - 演化代数：默认档 3–5 代 / 保守档 2 代（控查询成本）
  - Constraint 语义保真阈值：默认档 高保真（防跑题） / 保守档 严格原文意图一致
- 退化签名：若缺少 Constraint 语义约束，变异体会迅速漂移成无害擦边球，造成假阳性高分。
- 嫁接落点：对应「破甲制作 v3」`generate ↔ verify` 演化回边，以及「破甲炼化 v2」`compose`（WildTeaming Mine→Compose 交叉算子）。
- 风险与合规：严格限定于受控安全评测环境。

### R-07 DeepTeam · 40+ 脆弱面与 RAG/Agent 行为红队框架
- 来源：WEB: https://github.com/confident-ai/deepteam
- 槽位：应用层红队框架 / 指标库
- 家族：F8（智能体工作台规范）
- 浓度：中（面向应用、RAG 与 Agent 系统的端到端脆弱性评测）
- 语义指纹：把红队靶心从“裸大模型”拉到“完整 AI 应用（系统提示词 + 知识库 + 工具链）”，覆盖权限越界、提示词泄漏、PII 泄露与偏见等 40+ 风险面。
- 机制要点：
  ・区分「漏洞类型（Vulnerability）」与「攻击手法（Attack）」两个正交轴，便于定位根因；
  ・支持多轮线性/树状进阶探测与自定义业务策略合规检查；
  ・输出结构化风险摘要，便于研发团队逐项修复。
- 剂量参数：
  - 攻击增强轮次：默认档 每漏洞 2 种手法 / 保守档 每漏洞 1 种基线手法
- 退化签名：仅做应用黑盒测试难以区分是底层模型退化还是外围护栏/RAG 检索失守，需先跑 `recon` 护栏指纹。
- 嫁接落点：对应「破甲制作 v3」`recon` 应用层边界识别与 `report` 防御加固建议清单。
- 风险与合规：仅限对自有或获授权 AI 应用执行安全评估。

### R-08 Meta PurpleLlama CyberSecEval · 网络安全风险与过拒率（FRR）双轨基准
- 来源：WEB: https://github.com/meta-llama/PurpleLlama
- 槽位：安全评测套件 / 误拒率对照
- 家族：F1（终端/控制台模拟）＋ F8（智能体工作台规范）
- 浓度：中（聚焦代码安全、攻防推理边界与 False Refusal Rate 平衡）
- 语义指纹：在评测网络安全与代码能力的同时强制同步测量**误拒率（FRR）**，量化模型是否因过度敏感而丧失正常防御/运维辅助能力。
- 机制要点：
  ・覆盖不安全代码生成、提示注入抵抗、攻防辅助合规性以及良性安全问答误拒率（FRR）；
  ・为安全领域「防御可用性 vs 滥用拦截率」提供可量化的 Pareto 评测思路。
- 剂量参数：
  - 良性防御样本配比：默认档 1:1（与敏感样本成对） / 保守档 1:2
- 退化签名：若忽略 FRR 只看拦截率，极易把“一刀切全拒”的不可用模型误判为最安全模型。
- 嫁接落点：对应「破甲制作 v3」`probe` 孪生锐度 $\Delta$ 与 `report` 的 $\Delta\text{OR}/\Delta\text{JB}$ 权衡分析。
- 风险与合规：遵守 Meta PurpleLlama 开源许可，仅供安全研究与防御评测。
